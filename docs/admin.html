Maintainer guide

Data that is cache-first and permission-first.

This page does not accept browser uploads: a local browser change is not a production update. Production data changes are reviewed, validated, committed, and deployed from the repository.

What the site stores

Only the minimum ranking fields: display name, nationality, age group, gender, event, division, and finish time. No email, phone, date of birth, account information, or split-level data is needed.

Allowed ingestion

Use a writtenly authorized HYROX export/API or a data supplier whose contract expressly permits this storage and public republication. Keep the licence and source records with each release.

Never scrape the portal

The HYROX website terms prohibit automated access and scraping. The repository intentionally has no scraper for the HYROX portal.

Data-subject requests

Before a public launch, publish a privacy notice, contact channel, retention schedule, and correction/removal process. Get jurisdiction-specific advice for PDPA/GDPR compliance.

Refresh a finished event

  1. Obtain the authorized source and record its licence.
  2. Set HYROX_RESULTS_API_TOKEN locally or as a GitHub Actions secret; it never reaches the static site.
  3. Run npm run refresh:api -- --full for initial backfill, then npm run refresh:api for newly completed events.
  4. Run npm test && npm run validate-data, review the diff, then commit and push.

The importer supports the documented independent HYROX Result API as an optional source. It is not affiliated with HYROX; confirm its rights to supply and your rights to republish data before use.
