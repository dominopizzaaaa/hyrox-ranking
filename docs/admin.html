Maintainer guide

Data that is cache-first and permission-first.

This page does not accept browser uploads: a local browser change is not a production update. Production data changes are reviewed, validated, committed, and deployed from the repository.

What the site stores

Only the minimum ranking fields: display name, nationality, age group, gender, event, division, and finish time. No email, phone, date of birth, account information, or split-level data is needed.

Allowed ingestion

Use an export or supplier whose terms expressly permit this storage and public republication. Keep the licence and source records with each release.

Never scrape the portal

The repository intentionally has no scraper for the HYROX portal. Its optional importer uses the independently maintained pyrox-client dataset instead.

Data-subject requests

Before a public launch, publish a privacy notice, contact channel, retention schedule, and correction/removal process. Get jurisdiction-specific advice for PDPA/GDPR compliance.

Refresh the cached results

  1. Confirm and record that the source terms permit public republication.
  2. Run python3 -m pip install -r requirements.txt.
  3. Run npm run refresh:pyrox -- --dry-run --max-events 1, then run npm run refresh:pyrox -- --full --confirm-republication-rights for the initial backfill.
  4. For later updates, run npm run refresh:pyrox -- --confirm-republication-rights.
  5. Run npm test && npm run validate-data, review the diff, then commit and push.

pyrox-client is independent of HYROX. A technical download path is not by itself a licence to republish participant data.
